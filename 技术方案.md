## 2. 核心模块设计

### 2.1 Copilot Adaptor（adaptor.go）

实现 new-api `ChannelAdaptor` 接口，是整个集成的唯一入口。

```Plain
请求进入 Adaptor：
  1. 从 meta 取 GitHub Token（Seat 映射已在 middleware 完成）
  2. GetCopilotToken(githubToken) → copilot_token + base_url（带缓存）
  3. 根据 meta.Mode / 路径判断：
     - chat/completions → 透传（模型名规范化）
     - messages（Anthropic）→ TranslateAnthropicToOpenAI → 转发 → 响应转换
     - embeddings → 透传
  4. SetupRequestHeader：注入完整 IDE Headers
  5. DoResponse：
     - 非 Claude / 非 messages 路径：透传 resp.Body
     - messages 路径 + stream：流式状态机转换
     - messages 路径 + 非 stream：TranslateOpenAIToAnthropic
```

### 2.2 Token Exchange + 主动刷新（token.go）

**两级缓存 + 主动刷新（参考 copilot-api）**：

```Plain
请求来时：
  检查进程内 sync.Map
    命中且未过期（expires_at - 5min > now）→ 直接返回
    未命中或过期：
      尝试 Redis（key = copilot:token:sha256(githubToken)）
        命中 → 写回 sync.Map，返回
        未命中 → 发起 Token Exchange HTTP 请求
          成功 → 写 sync.Map + Redis（TTL = expires_at - now - 5min）
                 启动后台 goroutine 按 refresh_in - 60s 主动刷新

主动刷新 goroutine：
  sleep(refresh_in - 60s)
  重新 Token Exchange
  更新 sync.Map + Redis
  继续下一次 refresh 调度

错误处理：
  401 → 返回用户 401（GitHub Token 无效）
  403 → 返回用户 403（无 Copilot 订阅）
  429 → 指数退避重试 3 次
  5xx → 有缓存则降级使用旧 token，无则 502
```

### 2.3 完整 IDE Headers（headers.go）

```Plain
必须注入的 10 个 Header（任意缺少可能 403 或行为异常）：

Authorization                            Bearer {copilot_token}
Content-Type                             application/json
editor-version                           vscode/{动态版本}       ← 关键，需定期更新
editor-plugin-version                    copilot-chat/0.26.7
user-agent                               GitHubCopilotChat/0.26.7
copilot-integration-id                   vscode-chat
openai-intent                            conversation-panel
x-github-api-version                     2025-04-01
x-request-id                             {uuid.NewString()}      ← 每次唯一
x-vscode-user-agent-library-version      electron-fetch

条件 Header：
X-Initiator                              user / agent（按消息历史判断）
copilot-vision-request                   true（含图片时）
```

**版本号热更新机制**：

```Plain
优先级：
  1. 环境变量 COPILOT_EDITOR_VERSION（立即生效，无需重启）
  2. 动态从 AUR 拉取（24h 缓存）
  3. 硬编码 fallback（"1.104.3"）

监控告警：
  403 错误率 > 1% → 立即告警
  → 检查 cc-switch CHANGELOG → 更新环境变量 → 无需重启
```

### 2.4 Anthropic ↔ OpenAI 协议转换

#### 请求转换要点（anthropic_to_openai.go）

```Plain
难点一：消息顺序重排
  Anthropic user 消息可能包含 tool_result block
  tool_result 必须转换为 role="tool" 且排在用户内容之前
  否则 OpenAI API 报序列错误

难点二：thinking block 处理
  Anthropic assistant 消息中的 thinking block 无 OpenAI 对应
  必须合并进 content 文本，否则多轮对话上下文断裂

难点三：max_tokens 必填
  Anthropic 协议中 max_tokens 必填
  OpenAI 可选；但当外部是 Anthropic 客户端时，网关必须确保转发时有合理的 max_tokens
  从 /models 动态获取该模型的 max_output_tokens，fallback 8192

难点四：模型名规范化
  claude-sonnet-4-5 / claude-sonnet-4-20250514 → claude-sonnet-4
  claude-opus-4-5 → claude-opus-4
  Copilot 不接受带子版本号的模型名，否则 400
```

#### 流式响应转换（stream_translator.go）

```Plain
状态机维护：
  MessageStartSent  bool         是否已发出 message_start
  ContentBlockIndex int          当前 block 编号（从 0 开始递增）
  ContentBlockOpen  bool         当前是否有 block 开着
  ToolCallBlocks    map[int]...  OpenAI tool_call index → Anthropic block 映射

转换规则：
  首 chunk                → message_start（含 usage 初始值）
  delta.content != ""     → 若有 tool block 开着则先 stop，开 text block，发 text_delta
  delta.tool_calls 新 ID  → 若有 block 开着则先 stop，开 tool_use block
  delta.tool_calls 参数   → input_json_delta 追加到对应 tool block
  finish_reason != ""     → 关所有开着的 block，发 message_delta + message_stop
  [DONE]                  → 结束

关键边缘 case：
  同一 chunk 中同时有 content 和 tool_calls → 先处理 content，再处理 tool_calls
  多个并发 tool_calls（parallel tool calls）→ 通过 index 区分，各自维护 block
```

### 2.5 Seat 映射（service/seat/binding.go）

```Plain
请求链路：
  API Key → 解析 tenant_id（from new-api 现有 key 体系）
  X-User-Id Header → user_id
  查询 seat_bindings（Redis 10min 缓存 → PG 兜底）
  AES-256-GCM 解密 → github_token
  注入 meta.APIKey = github_token

加密方案：
  算法：AES-256-GCM
  密钥管理：AWS KMS / GCP KMS（密钥不落本地磁盘）
  存储格式：base64(iv || ciphertext || tag)
  解密时机：每次请求时实时调用 KMS 解密，明文不缓存到 Redis
```

### 2.6 多级限流（middleware/rate_limit.go 扩展）

```Plain
Redis Key：
  rl:seat:{seat_id}:conc       并发数（INCR/DECR）
  rl:seat:{seat_id}:qpm        每分钟请求数（滑动窗口）
  rl:global:conc               全局并发数

Lua 原子脚本（一次 roundtrip 完成三个检查）：
  1. seat 并发 >= seat_conc_limit  → 返回 429（SEAT_CONCURRENT）
  2. seat QPM >= seat_qpm_limit    → 返回 429（SEAT_QPM）
  3. global 并发 >= global_limit   → 返回 503（GLOBAL_OVERLOAD）
  全部通过 → INCR seat conc + global conc

defer（请求结束无论成败）：
  DECR rl:seat:{seat_id}:conc
  DECR rl:global:conc

Fail-open：
  Redis 不可用 → sync.Map 本地计数（上限 = Redis 配置 × 50%）
  记录 WARN 级审计日志，供事后分析
```

## 3. 数据库 Schema

```SQL
-- Seat 绑定（核心）
CREATE TABLE seat_bindings (
    id               BIGSERIAL PRIMARY KEY,
    tenant_id        UUID NOT NULL,
    user_id          VARCHAR(128) NOT NULL,
    seat_id          VARCHAR(128) NOT NULL UNIQUE,
    encrypted_token  TEXT NOT NULL,
    account_type     VARCHAR(32) DEFAULT 'individual',
    status           VARCHAR(32) DEFAULT 'active',
    bound_at         TIMESTAMPTZ DEFAULT NOW(),
    last_used_at     TIMESTAMPTZ,
    UNIQUE (tenant_id, user_id)
);
CREATE INDEX idx_seat_lookup ON seat_bindings(tenant_id, user_id);

-- 计费事件
CREATE TABLE billing_events (
    id               BIGSERIAL PRIMARY KEY,
    tenant_id        UUID NOT NULL,
    user_id          VARCHAR(128) NOT NULL,
    seat_id          VARCHAR(128) NOT NULL,
    request_id       VARCHAR(128) NOT NULL UNIQUE,
    model            VARCHAR(64),
    protocol         VARCHAR(16),
    status_code      INTEGER,
    input_tokens     INTEGER DEFAULT 0,
    output_tokens    INTEGER DEFAULT 0,
    duration_ms      INTEGER DEFAULT 0,
    billed_at        TIMESTAMPTZ DEFAULT NOW(),
    billing_cycle    VARCHAR(7)
);
CREATE INDEX idx_billing_tenant_cycle ON billing_events(tenant_id, billing_cycle);

-- 审计事件（热数据，30 天后归档）
CREATE TABLE audit_events (
    id             BIGSERIAL PRIMARY KEY,
    tenant_id      UUID NOT NULL,
    user_id        VARCHAR(128),
    seat_id        VARCHAR(128),
    model          VARCHAR(64),
    protocol       VARCHAR(16),
    input_tokens   INTEGER,
    output_tokens  INTEGER,
    status_code    INTEGER,
    duration_ms    INTEGER,
    client_ip_hash VARCHAR(64),
    created_at     TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_audit_tenant_time ON audit_events(tenant_id, created_at DESC);

-- Copilot Token 缓存（Redis 优先，PG 作 Redis 不可用时的兜底）
CREATE TABLE copilot_token_cache (
    github_token_hash VARCHAR(64) PRIMARY KEY,
    copilot_token     TEXT NOT NULL,
    base_url          VARCHAR(256),
    expires_at        TIMESTAMPTZ NOT NULL,
    refresh_in        INTEGER,
    updated_at        TIMESTAMPTZ DEFAULT NOW()
);
```

## 5. 监控告警


|                       |         |                  |                                |
| --------------------- | ------- | ---------------- | ------------------------------ |
| 指标                    | 告警阈值    | 含义               | 响应动作                           |
| Token Exchange 403 率  | > 1%    | IDE Headers 版本过时 | 更新 COPILOT_EDITOR_VERSION 环境变量 |
| Token Exchange 429 率  | > 5%    | Token 换取过于频繁     | 检查 refresh_in 刷新逻辑             |
| Token Exchange P95 耗时 | > 500ms | GitHub API 响应慢   | 检查网络，扩展 Redis 缓存               |
| Seat 限流命中率            | > 20%   | 并发配置偏低           | 调整 RATE_LIMIT_SEAT_CONCURRENT  |
| 全局并发利用率               | > 80%   | 需扩容              | 增加 Deployment 副本               |
| Redis 不可用时长           | > 30s   | Fail-open 已启用    | 紧急恢复 Redis                     |
| Anthropic 流式转换错误率     | > 0.1%  | 状态机边缘 case       | 查日志，修 stream_translator        |
