# 订阅 API 服务客户视角验收报告（2026-04-24）

## 1. 验收目标

以“已购买/已获得 API Token 的订阅客户”视角，验证以下核心能力：
- 可发现模型（`/v1/models`）。
- 可正常完成一次对话请求（`/v1/chat/completions`）。
- 非法 Token 会被拒绝（鉴权）。
- 超出限流策略时返回可识别错误（限流防护）。
- 关键行为可在审计数据中观察（可追踪性）。

## 2. 测试环境与账号

- 服务地址：`http://localhost:3000`
- 客户 Token（测试）：`e2e-token`
- 业务租户头：`X-Tenant-Id: default`
- 验收时间：2026-04-24 17:13 ~ 17:19（UTC+8）

## 3. 验收用例与结果

### 用例 A：模型列表查询（客户入口可用性）
- 请求：`GET /v1/models`
- 认证：`Authorization: Bearer <客户Token>`
- 实际结果：`HTTP 200`
- 返回摘要：包含 `gpt-4o-mini`
- 结论：**通过**

### 用例 B：标准对话请求（核心价值链路）
- 请求：`POST /v1/chat/completions`
- 请求体：`model=gpt-4o-mini`，单轮消息“请回复：验收通过”
- 实际结果：`HTTP 200`
- 返回摘要：`assistant.content = "验收通过"`
- 结论：**通过**

### 用例 C：非法 Token 鉴权（安全基线）
- 请求：`POST /v1/chat/completions`
- 认证：`Authorization: Bearer invalid-token`
- 实际结果：`HTTP 401`
- 返回摘要：`Invalid token (...)`
- 结论：**通过**

### 用例 D：并发限流（服务保护机制）

### 用例 E：审计可观测性（运营/追踪）
- 观察源：`audit_events` 表
- 实际结果：可见大量 `status_code=200` 的记录（含 `request_id`、`seat_id`、`duration_ms`）。
- 额外观察：本轮压测触发的 429 未在 `audit_events` 中出现。
- 结论：**部分通过**（成功链路可追踪；失败链路观测有缺口）

## 4. 验收结论（客户视角）

### 4.1 总体结论
- **客户可用性结论：通过（可上线试运行）**
- 核心“买了 Token 就能调通模型并拿到回复”链路已成立。
- 鉴权与限流行为符合预期，系统具备基础安全与保护能力。

### 4.2 上线前建议（P1）
- 建议补齐 4xx（尤其 401/429）到审计事件，便于客服、运营、SRE 做问题追踪与容量分析。
- 建议统一错误响应结构（当前 429 为字符串字段，401 为标准 error object），降低客户 SDK 适配复杂度。

## 7. 手工验收步骤（可直接复制执行）

> 目标读者：第一次接触本服务的 API 订阅客户。

### Step 0：准备
- 打开终端。
- 准备以下参数：
  - `BASE_URL=http://localhost:3000`
  - `TOKEN=<你的客户API Token>`
  - `TENANT_ID=default`（若你有独立租户，替换为实际值）

### Step 1：检查模型列表（服务可用）
执行：

```bash
curl -i "$BASE_URL/v1/models" \
  -H "Authorization: Bearer $TOKEN"
```

判定标准：
- 看到 `HTTP/1.1 200`（或 `HTTP/2 200`）即通过。
- 返回体 `data` 内至少有一个模型。

### Step 2：发起一次对话（核心能力）
执行：

```bash
curl -i "$BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-Tenant-Id: $TENANT_ID" \
  -d '{
    "model":"gpt-4o-mini",
    "messages":[{"role":"user","content":"请回复：验收通过"}],
    "stream":false
  }'
```

判定标准：
- `HTTP 200`。
- 返回体有 `choices[0].message.content`，内容语义正常。

### Step 3：验证鉴权失败（安全）
执行：

```bash
curl -i "$BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer invalid-token" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"test"}]}'
```

判定标准：
- 返回 `HTTP 401`（或平台定义的未授权状态码）。

### Step 4：验证限流（保护机制）
执行（并发 12 请求）：

```bash
python3 - <<'PY'
import json
from collections import Counter
from concurrent.futures import ThreadPoolExecutor, as_completed
import urllib.request

BASE_URL="http://localhost:3000"
TOKEN="<你的客户API Token>"
TENANT_ID="default"

url=f"{BASE_URL}/v1/chat/completions"
headers={
    "Authorization": f"Bearer {TOKEN}",
    "Content-Type": "application/json",
    "X-Tenant-Id": TENANT_ID,
}
body=json.dumps({
    "model":"gpt-4o-mini",
    "messages":[{"role":"user","content":"并发限流验收"}],
    "stream":False
}).encode()

def one():
    req=urllib.request.Request(url, data=body, headers=headers, method="POST")
    try:
        with urllib.request.urlopen(req, timeout=30) as r:
            return r.status
    except Exception as e:
        return getattr(e, "code", "ERR")

ret=[]
with ThreadPoolExecutor(max_workers=8) as ex:
    fs=[ex.submit(one) for _ in range(12)]
    for f in as_completed(fs):
        ret.append(f.result())
print(dict(Counter(ret)))
PY
```

判定标准：
- 结果里出现 `429`，表示限流生效。
