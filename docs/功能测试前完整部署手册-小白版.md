# 功能测试前完整部署手册（新手超详细版）

> 适用项目：`feifan-new-api`（当前进度含 Copilot 网关改造）  
> 阅读方式：从上到下照做，不要跳步骤。  
> 本文目标：把环境部署到“可以开始功能测试”的状态。

---

## 0. 先看这个：你现在要做什么

你要完成 4 件事：

1. 准备好本地环境（工具 + 代码）。
2. 构建前端并启动后端服务。
3. 进入管理台完成基础配置（管理员、Seat、Token、Channel）。
4. 做一遍测试前检查（构建通过 + 服务可用 + 数据落库）。

只要做完，功能测试就可以开始。

---

## 1. 执行约定（避免新手常见误操作）

请遵守这三个约定：

1. **命令在哪里执行**：都在终端执行（macOS 的 Terminal/iTerm/Cursor Terminal 都行）。
2. **每步都看结果**：执行完一条命令，先确认“预期结果”再继续。
3. **不要同时开多个后端实例**：避免端口冲突（3000 端口）。

---

## 2. 方案选择（先走最简单）

你有 2 条路：

- 路线 A（推荐）：**本地部署**，最适合新手，先跑通功能测试。
- 路线 B（可选）：**K8s 部署**，适合预发/线上环境。

本文先完整讲路线 A，最后给路线 B。

---

## 3. 环境准备（第一次做必须完成）

### 3.1 需要的软件

- Git
- Go（建议 `1.22+`）
- Node.js（建议 `20+`）
- npm（Node 自带）
- （可选）bun
- （可选）Docker / Docker Compose

### 3.2 检查是否安装成功

在终端执行：

```bash
git --version
go version
node -v
npm -v
bun -v
docker -v
docker compose version
```

预期：

- 前 4 条有版本号就行。
- `bun` 没有可忽略（本文默认用 npm）。
- `docker` 没有也不影响本地路线 A。

如果报 `command not found`：

- 说明该工具没装好，先安装再继续。

## 5. 创建环境变量文件（新手推荐最简版）

### 5.1 在项目根目录创建 `.env`

```bash
cat > .env <<'EOF'
# 必填，随便先给随机字符串（不要太短）
SESSION_SECRET=change-me-session-secret-please-123456
CRYPTO_SECRET=change-me-crypto-secret-please-123456

# 本地最简走 SQLite：SQL_DSN 和 REDIS_CONN_STRING 留空即可
# SQL_DSN=
# REDIS_CONN_STRING=

# Copilot 相关
COPILOT_EDITOR_VERSION=vscode/1.104.3
EOF
```

### 5.2 为什么这两个 Secret 必填

- `SESSION_SECRET`：登录态签名，避免会话问题。
- `CRYPTO_SECRET`：Seat 绑定里的 GitHub Token 加解密依赖它。

## 6. 构建前端（非常关键，别跳）

> 这一步失败会直接影响后端启动和页面访问。

在项目根目录执行：

```bash
npm --prefix ./web install --legacy-peer-deps
npm --prefix ./web run build
```

预期：

- 命令成功结束（退出码 0）。
- 生成目录 `web/dist`。

你可以验证一下：

```bash
ls web/dist
```

如果出现 `main.go: pattern web/dist: no matching files found`：

- 说明你没完成这一步，重新执行上面两条 npm 命令。

---

## 7. 启动后端服务（本地）

在项目根目录执行：

```bash
go run main.go
```

预期现象：

- 终端持续输出日志（这是正常的）。
- 能访问 `http://localhost:3000`。

### 7.1 重要：这个终端不要关

`go run` 是前台运行。  
如果你关掉这个终端，服务就停了。

建议：

- 新开第二个终端做后续 `curl` 检查命令。

## 8. 首次初始化管理员账号

### 方式 A（推荐）：网页初始化

1. 浏览器打开 `http://localhost:3000`
2. 根据页面提示创建管理员账号（例如 `root`）

### 方式 B（备用）：API 初始化

```bash
curl -X POST "http://localhost:3000/api/setup" \
  -H "Content-Type: application/json" \
  -d '{
    "username":"root",
    "password":"Password123",
    "confirmPassword":"Password123",
    "SelfUseModeEnabled":true,
    "DemoSiteEnabled":false
  }'
```

预期：

- 返回成功响应（通常是 `success: true`）。

## 9. 登录管理台后要做的 3 个基础配置

登录后，请按顺序做：

### 9.1 配置 Seat 绑定

- 入口：左侧菜单 `Seat 绑定`
- 页面路径：`/console/seat-binding`
- 创建时填写：
  - `tenant_id`：新手先填 `default`
  - `user_id`：填用户 ID（通常 root 是 `1`）
  - `seat_id`：自定义，比如 `seat-a`
  - `github_token`：你的 GitHub token
  - `account_type`：默认即可

### 9.2 创建测试 Token

- 在 Token 管理里创建一个可用于 API 调用的测试 Token。
- 复制保存（后续调接口要用）。

### 9.3 创建 Copilot 渠道

- 新建 Channel，类型选 Copilot。
- 模型可先写你测试用模型（如 `gpt-4o-mini`）。

## 11. 功能测试前“运行态检查”（建议执行）

## 11.1 健康检查

```bash
curl "http://localhost:3000/api/status"
```

预期：返回服务状态（非 5xx）。

## 11.2 Seat 绑定接口检查

```bash
curl "http://localhost:3000/api/seat_binding/"
```

如果返回未授权：

- 优先在管理台页面操作，不要硬测接口。
- 或补充管理接口要求的用户上下文请求头。

## 11.3 数据库表检查（SQLite）

```bash
python3 - <<'PY'
import sqlite3
conn=sqlite3.connect('one-api.db')
cur=conn.cursor()
cur.execute("SELECT name FROM sqlite_master WHERE type='table' AND name='audit_events'")
print(cur.fetchone())
conn.close()
PY
```

预期：输出 `('audit_events',)` 或同义结果，表示审计表存在。

## 12. 新手最容易卡住的 6 个问题

### 问题 1：`bun: command not found`

- 原因：没安装 bun。
- 处理：全程改用 npm（本文已经用 npm 命令）。

### 问题 2：`web/dist` 不存在

- 原因：前端没 build。
- 处理：重新执行：
  - `npm --prefix ./web install --legacy-peer-deps`
  - `npm --prefix ./web run build`

### 问题 3：3000 端口被占用

- 现象：`go run` 启动失败。
- 处理（macOS）：
  - `lsof -i :3000`
  - 结束占用进程后重启服务。

### 问题 4：`Unauthorized, New-API-User header not provided`

- 原因：调用了需要用户上下文的后台接口。
- 处理：优先用管理台页面操作；或补请求头。

### 问题 5：Copilot 调用返回 404/403

- 原因通常在上游能力，不一定是本地代码问题：
  - token 权限不够
  - 账号无 Copilot 能力
  - 上游策略限制
- 建议：先完成管理台流程、限流、审计相关测试，再处理上游可用性。

### 问题 6：`go test` 慢或失败（网络/缓存）

- 先重试一次。
- 再检查网络和 Go 依赖下载是否正常。
