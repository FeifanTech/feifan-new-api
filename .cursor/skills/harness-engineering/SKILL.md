# Harness Engineering（缰绳工程）Skill

## 定位

**Harness** = 模型以外的系统层：如何**约束、供给、验证、纠偏** Agent，使结果可重复、可审计、可止损。  
本 Skill 提供**最小可执行检查点**与**红旗**；概念映射见 `RFC/harness-engineering/RFC-harness-engineering-mapping.md`。

**与 Human Gate**：Harness 管「机械与流程是否过关」；Human Gate 管「人是否承担风险与范围」。二者都须满足，不能互相替代。

- 用户意图：设计/评审多步 Agent 流程、改进工具与上下文策略、在实现前后落实「每步可验证」、排查「Agent 看似对了但系统不可靠」类问题。

## 红旗清单（触达即停，交人决策）

1. **工具/API/文件操作失败后仍继续后续步骤，且未记录失败原因与补救策略**  
   常见借口：「模型会自己纠正」「先走完流程」。→ 触达即停，交人决策。

2. **无上限的自动重试或循环调用（token/费用/时间），且无「成本包络」或等价中止条件**  
   常见借口：「多试几次总能好」。→ 触达即停，交人决策。

3. **向 Agent 暴露过多松散工具，且无「默认子集」与选用准则**  
   常见借口：「工具多更灵活」。→ 触达即停，交人决策（参考业界：少而硬的工具集通常更稳）。

4. **关键路径无最小验证（测试、lint、契约、或明确的人工验收步骤）即宣称完成**  
   常见借口：「改动小」「后面一起测」。→ 触达即停，交人决策。

5. **多步执行无结构化记录（何工具、何输入输出、何判定），导致无法复盘**  
   常见借口：「对话里都有」。→ 触达即停，交人决策；至少补 `memory/changelog.md` 或 PR 描述中的逐步摘要。

## AI-DLC Stage × 最小 Harness 检查点

执行或评审任务时，按当前 **Stage** 勾选；若尚无 Plan，按任务实际阶段近似对应。

| Stage（近似） | Context | Tools | Verification | Cost 意识 | Observability |
|---------------|---------|-------|--------------|-----------|---------------|
| **需求 / Intent** | 只注入 PRD/问题陈述/约束，避免无关代码库全文 | 少工具；检索类工具须有查询边界 | 验收标准可测试、无歧义（可与 product-design-principles 交叉） | 限制发散轮次（会话内声明最大澄清轮数） | 记录 Intent 摘要与待定假设到 `memory/` 或 PR |
| **设计 / 方案** | 架构图、接口表、边界、NFR 按需加载 | 不启用执行类工具除非为读-only 分析 | 方案检查项有明确通过/不通过（可与 architecture-principles 交叉） | 避免长上下文重复粘贴；用引用与链接 | ADR/决策进 `memory/decisions.md`（Proposed→Accepted） |
| **实现** | 相关模块路径、接口契约、错误处理约定 | 写文件/终端类工具**须**有错误处理与二次确认（团队约定） | **每步**：改代码 → 至少一种验证（测试/lint/手工步骤） | 单次任务声明 token/调用上限（团队自定数字） | Commit/PR 说明含任务或 Plan-ID；关键中间结论可记 changelog |
| **测试 / 验证** | 测试范围、环境、数据说明 | 测试命令可复现 | 失败用例不「静默跳过」；须修复或登记 | CI/本地资源有上限意识 | 失败日志可定位到步骤与输入 |
| **发布 / 运维** | 发布说明、回滚、监控 | 部署类工具走专用 guard（如 k8s-deploy-guard） | 发布 checklist 全绿或已登记例外 | 生产变更窗口与回滚成本 | 发布后观测项与负责人 |

## 最小执行清单（任务开始前自检）

- [ ] **上下文**：本步需要的最小文件/决策/接口是否已列出？是否避免无关大段粘贴？
- [ ] **工具**：本步启用哪些工具？失败时（超时、4xx/5xx、空字段）默认动作是什么？
- [ ] **验证**：本步结束用什么**客观标准**判定通过（命令、测试、diff、人工勾选）？
- [ ] **成本**：是否有可能无限循环？是否设置中止条件（轮次/时间/预算）？
- [ ] **记录**：关键步骤与结果是否可写入 PR 描述、`memory/changelog.md` 或会话摘要？

## 产出物建议

- **设计/评审**：一页「Harness 视图」——上下文来源、工具列表、每步验证、中止条件、记录落点。
- **排障**：按失败类型归类——上下文错误 / 工具错误 / 验证缺失 / 成本失控 / 无观测，并给出下一动作。
